# Changelog

## Unreleased

### Behavior changes

- Unknown language names now raise `ValueError` listing the available languages (for example `languages="englsh"` used to silently disable detection); an empty selection also raises. Language names are case-insensitive.
- `ShieldResult.original` is now always the exact input, and `clean` is the input with only matched spans masked. Invisible characters (zero-width spaces/joiners, bidi marks, soft hyphens, tag characters, variation selectors) are ignored for matching only, so emoji ZWJ sequences such as `👩‍💻` are no longer altered. Invisible-character obfuscation (`f\u200bu\u200bc\u200bk`) is still caught and the mask now covers the whole original span, invisible characters included; `Match.position`/`length` index the original text.
- Ordinary double letters no longer create matches on their own: `cook`, `cookie`, `good`, `annals` and ~1,000 other dictionary words were flagged because repeated-letter expansion read them as `cok`, `god`, `anal`. Runs of three or more identical letters (`fuuuck`, `shiiiit`) and doubles of letters English almost never doubles (`fuuckin`, `shiit`; derived from double-letter frequencies in /usr/share/dict/words) are still treated as deliberate obfuscation.
- German normalization was quadratic on runs of `s` (`"s" * 32000` with `languages="german"` took ~5s): it now starts only at the first `s` of a run. Compound parts are also compared in their normalized spelling (German `beschaemendes` is read as `beshaemendes`).
- Matches no longer bleed into the next word across punctuation: `shit, said` was reported as `shits` and masked `*******aid`; `fuck, yourself` and `f*ck yourself` masked `rself`'s prefix. Deliberate spaced obfuscation (`f u c k`, `f, u, c, k`, `@ss holes`) is still caught.
- The compound-word rule only counts a profanity that directly abuts the match, so ordinary words are no longer flagged because a short entry occurs elsewhere in them (`zero\u200bwidth` masked `dth`, `anticipate`, `advertisement`, `holster`, ...). Combined with the change above, 2,355 of 234,456 dictionary words were flagged before and 830 are now, none of them newly.
- `Shiite`/`Shiites` were added to the bundled false positives.
- `block` keeps the curated severity of words already in the dictionary (blocking `coon` no longer lowers it from `extreme` to `high`); new words default to `high` as before. An explicit `block` now overrides a bundled false positive for that word (`block=["class"]` masks `class`). `allow` still wins over `block`.
- Blank or whitespace-only `allow`/`block` entries are ignored (`block=[""]` used to hang forever), entries are stripped, and a single string counts as one word. Non-string entries raise `TypeError`.
- Where readings of different entries overlap, the one covering more of the text is chosen rather than the longest entry's: `whooore` is reported as one moderate `whore` (`*******`) instead of a high `hooore` (`w******`), and copies are masked whole (see Fixes). With `minimum_severity`, a reading that would be reported always wins over one that would not, so `whooore` at `high` is still `w******`.
- Combining languages (`languages=[...]` with more than one entry, or `all_languages=True`) only merges accent/diacritic substitutions, as upstream Blasp does, so `sock` is no longer masked in an English+German filter.

### New

- `driver="pattern"` option on `ProfanityFilter`, `filter_text`, `check_text` and `clean_text`: a port of Blasp's literal `PatternDriver` (exact, whole-word, case-insensitive matches). The default `driver="regex"` is unchanged.

### Fixes

- Fixed catastrophic regex backtracking: `check("*" * 22)` took ~29s and `"*" * 24` never finished. Matching is now linear in the input length: 500-character adversarial inputs built from every bundled separator and substitution character finish in well under a second in every language. Very long runs of interchangeable characters are shortened for matching only (masks still cover the whole run); a letter inside a word matches at most 64 other substitutes (`uυuυ...`) or 32 censoring stretches (`f*f*f*...`) in a row.
- A profanity repeated without a separator could come back clean or half masked (`twattwat`, `twaattwaat`, `"baastard" * 3`, `blowjobblowjob`, `5h1t5h1t`, `jihadjihad`; main and earlier rounds alike): a stretched run at the end of one copy took the next copy's first letter, which finditer() then skipped, or a different entry spelled across the junction of two copies took its letters first. Matches are no longer accepted one at a time, longest entry first: each pass collects every reading of every entry (the matches, shorter readings that give a stretched run's last letters to a copy that follows, readings starting at any split near the end of a run of their first letter, or ending inside a deliberate final run of their last letter, where another reading meets them, a run being any characters that letter accepts (`bitttch|hell`, `shittttt|wat`, `bitchΗ|hell`, `shittτ|twat`), and the copies such readings free; each match is judged once per pass, so glued copies cost linear time), then selects the non-overlapping set that covers the most letters and digits, then the most characters that spell something (symbols standing for letters; not whitespace or separators no letter stands for), then the one with the fewest matches, longer entries and earlier positions. A match that would be reported under `minimum_severity` is never dropped for one that would not. Neighbours that a compound or a chain of rare doubles needs are chosen together, in time linear in the number of readings. Copies through a separator (`sluut,sluut`, `5hit-5hit`, `kums,kums`), glued phrases (`beef curtainsbeef curtains`, `raging bonerraging boner`, `soltar pedossoltar pedos`) and copies starting with a symbol (`@ne @ne` in French, not `@|ne @ne` read as `nene`) are resolved too. A sweep of every bundled entry, plain and stretched, repeated 1-4 times with and without separators went from 17,644 failing texts to 789 (doubling an ordinary letter, which makes a different word by design, is not counted).
- Letters of multi-letter substitution keys (German `sch`, `ch`, `ck`, `ie`, `ei`, `eu`, ...; Spanish `ll`, `ch`; French `qu`, `ph`) can be obfuscated or stretched individually: such entries get a second expression spelled per letter (`5chwuler`, `schhmähliches`, `heuuchlerische`). German normalizes stretched `sch` (`s+c+h+`) and Spanish whole runs of `r`, so `cerrrdo` no longer reads as an ordinary double. German single-language checks cost about 50% more for this.
- Chains of rarely doubled candidates (`biitchbiitch`, `biitchbiitchfuck`, `bitchhbiitch`, `damnnbiitch`) are caught: neighbouring candidates that only qualify together are selected together, each through any side that has a neighbour (`bitchhbiitch` stayed clean when its first candidate was judged by its missing left neighbour). Two-letter entries (`zu`, `po`) support no chain, and a link that leaves its vowel out needs a word edge or a match on both sides (`shtdck` and `ccksck` are caught, `sangreeroot` stays clean).
- Block entries are matched separately from the bundled words and from each other: bundled detection runs exactly as without a block list, each block entry is detected on its own on the same input (its own text found as typed, before language normalization and run shortening, plus every reading of its obfuscated forms that holds, overlapping or not; both drivers keep every occurrence), and the result masks everything any of them finds. Every reported match has the highest severity found in its region (overlapping findings), and the score counts every distinct span found. So adding a block entry never unmasks a character and never lowers a severity or the score (`n!gger` with `block=["n!gger"]` stays extreme, score 100; `x-y-z` with `block=["xy", "yz"]` and, with `driver="pattern"`, `12-34-5678` with `block=["12-34", "34-5678"]` are masked whole). Before, block entries were interleaved with the bundled detection and could take its letters or change its passes: German `block=["Fischhändler"]` and `block=["schhh"]` and Spanish `block=["carrrro"]` stayed clean; `filter_text("n!gger", block=["!"], minimum_severity="extreme")` lost its extreme match; `ass hole` with `block=["ass"]` was cut to `*** hole`; `wanker` with `block=["wanker"]` at `high` came back clean; `as$*hell` with `block=["$"]` lost `ass`; `12-34-5678` with `block=["12-34", "34-5678"]` masked only one of them; `block=["z" + "o" * 10 + "q"]` missed `"z-" + "o" * 10 + "q"`. Block entries' expressions are spelled as the language normalizes the text (Spanish `j` + `r` * 11 + `j` with any separator) with the runs they need kept, and the bundled words count as compound parts for them. Matches are reported in text order, longer first, an entry's own text first among equal spans; each reports what no earlier match holds, so a longer match holding an entry is reported instead of it and overlapping ones (also two readings sharing a character normalization split, German `ssch` read as `sh` between copies of `schmaehliches`) each report their own part. A block word next to a bundled one no longer makes the bundled word a compound (`classocciso` with `block=["class"]` masks `class` only); it is judged as without the block list.
- An explicit block entry's own text is never vetoed by a heuristic guard: a match that is the entry as typed and not part of a longer alphanumeric token, or lies in a token of nothing but the entry repeated, skips the hex/UUID, substring, compound, cross-word, joined-word and elision guards and the false positives (`-12345678`, `12345678-`, `-deadbeef1-`, `12121212` for `1212` stayed clean). `ab` inside `ab12cd34ef` and obfuscated forms in hex-like tokens stay protected. Each token's shortest repeated unit is computed once per check, so repeated entries cost time linear in the match (`"12" * 64000` with `block=["12"]` took ~2.5s; 12,000 distinct `ab`/`8` matches in one token ~2.3s).
- The confirming pass only rescans regions the previous pass's masks can affect (exactly equivalent to a full rescan): a 100k-character text with a few matches is checked about twice as fast, and dense text about 20% faster.
- Match-dense text was quadratic (`"shit " * 512000` took ~80s with a one-word filter, now ~4s): accepted matches are masked once per pass instead of copying the text and shifting index lists per match.
- A block word now always matches its own text: `full-length`, `cross-site` and `niggardliness's` did not match because a run of repeated letters swallowed the separator the word spells later; entries with internal whitespace and, with `driver="pattern"`, entries that start or end with a symbol (`c++`, `100%`) did not match either; and an equally long bundled entry could claim part of it first.
- `hell, Lloyd`, `Hell, llama`, `hell - Lloyd` and `hell / Lloyd` were left unmasked: a match that runs into the next word is now retried before the gap between the words, whatever separator it holds. The retry scans each run of symbols once (`"h e l" + "!£" * 8000` took ~3s).
- Words joined by a separator no longer bleed into each other: `hell-Lloyd` was masked `*******oyd`, `shit-tom` `******om`. Symbols inside an obfuscated word (`fu-ckhead`, `a*s*s`, `f-u-c-kyou`), inflections (`fu-cking`), separators inside a dictionary word (`cock*kblocker`, `rapis(st`) and another profanity continuing the word (`ass-holefuck`, at every `minimum_severity`) keep the longer match.
- A match leaving the vowel out must spell the word's other letters with letters or specific substitutes: `*Lloyd` was masked `***oyd` (`*Ll` read as `hll`, as `*` stands for any letter), so `hell *Lloyd` lost its match to the next word. `fck`, `f--ck`, `dmn` and `$ht` are still caught; `*ll`, `*mn` and `*ht` no longer are.
- Runs of alternating case or interchangeable variants longer than 64 characters went undetected (`"f" + "uU" * 33 + "ck"`, `"f" + "uü" * 33 + "ck"`): only identical characters were shortened, case-sensitively. Runs of characters no expression tells apart are now shortened together.
- A stretched letter followed by a letter with a longer option starting the same way went undetected: German `z` may be spelled `tz`, so `kitttzler`, `butttze` and `schmutttzig` stayed unmasked. Such a run is now also read with the next letter spelled otherwise. Entries spelled with capitals (`Fukah`, `Fukker`) did not get their letters' substitutes or runs, so `ffukah` and `F<u#k/k` were only partly masked; entries now match their substitutions case-insensitively.
- Run shortening left complete occurrences of a block word made of one repeated character unmasked (`"-" * 8` with `block=["--"]` gave `******--`; `"💩" * 8` with `block=["💩💩"]` likewise). Runs of characters no letter accepts are no longer shortened, and shortened runs keep complete literal occurrences complete.
- A block word with a long run of one character (`"x" * 300`, `"u" * 100`) made runs keep that many characters, so stretched words (`"f" + "u" * 100 + "ck"`) stopped matching. Block entries now have their own run shortening, so the bundled words' runs keep only what those need, and block-only filters still match long runs (`block=["xy"]` masks `"x" * 80 + "y"`).
- Block and allow entries containing invisible characters never matched with the default driver (`block=["❤\ufe0f"]` left `❤\ufe0f` unmasked): entries are now normalized like the text (an entry with nothing visible left is ignored), and variation selectors and emoji tag characters right after a match are masked with it.
- Block and allow entries containing a character whose lowercase is longer than the character itself never matched their own text, with either driver: `block=["İzmir"]` left `İzmir` unmasked, because lowercasing turned the entry into `i̇zmir` with a combining dot. Such characters are now kept as they are, and matching is case-insensitive as before (`İZMIR` is masked too).
- Rarely doubled letters inside compounds (`biitchfuck`, `twaatfuck`) are caught; a match directly touching another match counts as a compound.
- Scanning long tokens was quadratic (`"a55" * 2000` took ~4.5s, `"shit" * 4000` ~33s): word, hex-token and letter contexts are now looked up in run indexes built once per check, overlap checks use bisect, and masking no longer copies the position map per match.
- Inflections are handled completely: `shittier`, `crappier` and `crappiest` were no longer caught; the y -> i endings (`-ies/-ied/-ier/-iest/-ily/-iness`) now count after a doubled consonant or when the y-adjective is a dictionary word.
- Obfuscated plurals across punctuation (`f, u, c, kheads`, `sh, itheads`) are caught again, without reintroducing `shit, s|ing` bleed.
- The compound-word guard judges the actual occurrence instead of the first one in the word (`shitxshithell` masked only `hell`).
- Repeated letters split by separators (`coo-on`, `pimm-mel`, `cell*lule`) are caught again, and `butt today` no longer loses its match to the following word.
- Block words long enough to need more than 99 regex groups (for example a 101-character word) matched nothing.
- Runs of a one-character block word (`"💩" * 8`) produced overlapping matches; with a callback mask, text after the run was deleted.
- `filter_text`, `check_text` and `clean_text` no longer rebuild the dictionary on every call (~1.5s each); compiled dictionaries are cached per option set (bounded, thread-safe) and shared with `ProfanityFilter` instances, and filters that only differ by their allow/block lists reuse each other's compiled expressions.

### Tooling

- `scripts/sync_from_blasp.py` now pulls only the per-language word lists from upstream and no longer overwrites `profy/data/global.json` or per-language substitutions, which are Profy-owned. Upstream and external word lists are stored as separate layers under `sources/` and assembled deterministically, so the two sync scripts no longer clobber each other. Sync metadata is rewritten only when upstream changes, and `--check` reports pending changes without writing.
- The release workflow verifies that the tag, `pyproject.toml` and `profy.__version__` agree, marks GitHub Releases as pre-releases only for PEP 440 pre-release versions, smoke-tests the built wheel in a clean virtualenv, and no longer skips already-published files silently. Manual runs are dry runs.
- CI tests Python 3.9-3.14 and enforces 100% line and branch coverage.

## 0.1.2

- Fixed a false positive where a legitimate word adjacent to digits was masked because of a contained profanity. For example `hello9` was cleaned to `****o9` (matching `hell`). The Scunthorpe-style substring guard previously only applied when the entire surrounding `\w`-context was purely alphabetic, so a trailing/leading digit disabled it. The guard now inspects the surrounding alphabetic run (via `_alpha_word_context`), so words like `hello9`, `9hello`, `shell9`, and `scunthorpe9` stay clean while bare profanities with appended digits (`hell9`, `ass9`) are still masked.
